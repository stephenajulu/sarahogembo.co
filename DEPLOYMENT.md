# Deployment Guide: sarahogembo.co

This repository is pre-configured for **zero-configuration, 1-tap deployments** across the top three cloud hosting platforms: **Netlify**, **Render**, and **Cloudflare (Pages & Workers)**.

---

## 1. Netlify (Automated via `netlify.toml`)

Netlify automatically detects `netlify.toml` located in the root repository.

### 1-Tap Deployment Steps:
1. Log in to [Netlify](https://app.netlify.com/).
2. Click **"Add new site"** → **"Import an existing project"**.
3. Select your Git provider (GitHub / GitLab) and select the `sarahogembo.co` repository.
4. Netlify will automatically populate:
   - **Build Command**: `hugo --gc --minify`
   - **Publish directory**: `public`
   - **HUGO_VERSION**: `0.160.1`
5. Click **"Deploy site"**.

All HTTP security headers (HSTS, CSP, X-Frame-Options), 1-year immutable caching for `/images/`, `/css/`, `/js/`, `/videos/`, no-cache for `/sw.js`, and canonical 301 redirects (`/resume`, `/credentials`, `/profile` → `/cv/`) are applied automatically via `netlify.toml`.

---

## 2. Render (Automated via `render.yaml` Blueprint)

Render supports Infrastructure-as-Code via `render.yaml`.

### 1-Tap Blueprint Deployment (Recommended):
1. Log in to your [Render Dashboard](https://dashboard.render.com/).
2. Click **"New +"** in the top navigation and select **"Blueprint"**.
3. Connect your repository.
4. Render will read `render.yaml` and configure:
   - **Service Name**: `sarahogembo-co`
   - **Environment**: `Static Site`
   - **Build Command**: `hugo --gc --minify`
   - **Publish Directory**: `public`
   - **Hugo Version**: `0.160.1` (automatically downloaded by Render)
   - **Security Headers & Immutable Caching**: Configured per route
   - **Redirects**: `/resume`, `/credentials`, `/profile` → `/cv/`
5. Click **"Apply"** / **"Create Blueprint"**.

### Alternative: Manual Static Site on Render:
If creating as a standalone Static Site instead of Blueprint:
- **Build Command**: `hugo --gc --minify`
- **Publish Directory**: `public`
- **Environment Variables**:
  - `HUGO_VERSION`: `0.160.1`
  - `HUGO_ENV`: `production`

---

## 3. Cloudflare (Pages & Workers)

Cloudflare offers two modern zero-downtime deployment paths:

### Option A: Cloudflare Pages (Git Integration — Recommended)
1. Go to your [Cloudflare Dashboard](https://dash.cloudflare.com/) → **Compute (Workers & Pages)** → **Pages**.
2. Click **"Connect to Git"** and choose `sarahogembo.co`.
3. Select **Framework preset**: `Hugo`.
4. Cloudflare automatically sets:
   - **Build command**: `hugo --gc --minify`
   - **Build output directory**: `public`
5. Under **Environment variables**, set:
   - `HUGO_VERSION` = `0.160.1`
6. Click **"Save and Deploy"**.

*Note: Cloudflare Pages automatically detects and enforces `public/_headers` (security & cache rules) and `public/_redirects` (canonical redirects) generated by Hugo from the `static/` folder.*

### Option B: Cloudflare Workers with Static Assets (`wrangler.jsonc`)
Modern Cloudflare Workers with Static Assets allows instant CLI or pipeline deployment:

```bash
# 1. Login to Cloudflare
npx wrangler login

# 2. Deploy (build runs automatically)
npx wrangler deploy
```

`wrangler.jsonc` specifies:
- `build.command`: `hugo --gc --minify`
- `assets.directory`: `public`
- `html_handling`: `auto-trailing-slash`
- `not_found_handling`: `404-page`
- `vars.HUGO_VERSION`: `0.160.1`

## Verification & Local Testing

Before deploying, you can test the production build locally:

```bash
# Production Hugo Build (Generates public/)
npm run build
# or directly:
hugo --gc --minify

# Local Cloudflare preview (simulates Cloudflare Worker edge assets)
npm run preview
```
